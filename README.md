## Как поменять период и этапы

Всё настраивается в `config.json` — его можно править прямо на GitHub (иконка карандаша), после сохранения сайт пересоберётся сам:

- `from` — с какой даты считать (сейчас `2026-11-01`);
- `until` — последняя дата, дальше которой отчёт не считает;
- `stages` — ID этапов amoCRM для колонок «Ждём задачу» (`wait_task`), «Демо / передано команде» (`demo_kp`) и «Задача / передано команде» (`handed`). ID этапов не меняются при переименовании, поэтому сборка не ломается, если этап переименуют. Если этап удалят или добавят новый — поправьте список.

Этапы воронки сейчас: Аутрич, потеплить · Общаемся · Илье на оффлайн · Ждем задачу (90051642) · Демо / Передано команде (85003050) · Задача / передано команде (90196978) · Вернуться позже.

## Обновление

- Автоматически — каждый понедельник в 10:00 по Москве (GitHub может запустить с задержкой в несколько минут).
- По запросу — вкладка Actions → «Обновить отчёт и сайт» → Run workflow.
- При любом изменении в репозитории (например, правке `config.json`).

Для свежих данных из amoCRM в Settings → Secrets and variables → Actions должны быть секреты `AMOCRM_TOKEN` и `AMOCRM_SUBDOMAIN` (или `AMOCRM_API_BASE`). Без них публикуется сохранённый снимок.

Локальная сборка: `node scripts/build_report_site.js` (доступы — из переменных окружения или `.env`).

Шаблон: `reports/q4-touches-dashboard/template.html`. Публикуемые файлы: `site/`. На сайт попадают только агрегированные цифры: имена контактов, заметки и токены не публикуются. D3 7.9.0 лежит локально.

Недели — понедельник–воскресенье с обрезкой по периоду, месяцы — календарные. Продолжающиеся контакты считаются отдельно за каждый период, поэтому суммы недель и месяцев не равны итогу за период.
